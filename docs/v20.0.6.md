# v20.0.6: observed activity and manager dependency integrity

The first nimpocket campaign exposed two source defects. Synchronous native
calls were absent from the pool-only activity view. Serial managers all received
the same next ticket ID before their outputs were persisted; later filenames
received global IDs while their dependencies retained provisional IDs.

The runtime now publishes safe metadata from actual ACP invocations and typed
updates: role, configured model and effort, task, area/ticket, native identity,
state and timestamps. Recent terminal summaries are bounded. Heartbeats and
stderr do not imply progress. The snapshot belongs to the live orchestrator PID
and kernel start time; missing observations remain unavailable. Status reads
committed area/ticket headings without refreshing, cleaning or initializing plan
state. It provides only existing canonical plan document links. No transcript,
command, prompt, scoped endpoint or credentials enter the activity snapshot.

Serial managers persist each completed submission before the next manager
receives an ID base. Concurrent completions rebase their submitted IDs and
structured dependencies together, retaining references to pre-existing tickets.
Unknown provisional references and self-dependencies fail before writes.
Only completed areas have their input hashes recorded. A manager ending without
`submit_tickets` fails visibly; explicit empty submissions remain legitimate.
Worker exceptions return to the owning loop rather than terminating its thread
without a completion. Difficulty prediction uses the configured Architect role;
the implementation coder retains its separate configured role.

Offline checks cover native conversation reuse, callback thread ownership,
missing/stale observations, safe metadata and paths, quiescence, unchanged Git
state on status reads, sequential and concurrent manager allocation, dependency
rebasing, missing MCP completion, and prediction role selection. ARC and ORC
exercise the actual shared ACP protocol fixture. No additional provider turn is
required for these changes.

The running nimpocket campaign remains owned by its existing coordinator.
Callback details require a legitimate runtime adoption boundary; a newer status
binary cannot invent observations from an older supervisor. Existing saved
incorrect ticket metadata requires a separately pinned, audited repair from the
original successful submissions. That repair changes IDs/dependencies only and
must run while the existing supervisor is verified paused and quiescent. It does
not infer cross-area dependencies that managers never submitted, replay manager
turns, change emulator code, or bypass review and quality gates.
