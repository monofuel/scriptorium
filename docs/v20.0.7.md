# v20.0.7: MCP thread ownership and valid prompt text

A production supervisor exited with SIGSEGV in ORC cycle collection while a
Mummy worker parsed an MCP request. The old registry returned the same traced
session, MCPort server and cyclic handler graph to different HTTP workers and
the application caller. Its registry lock did not cover the subsequent server
handling, initialization or reference-count operations. Nim ORC reference
counts are not atomic and cyclic graphs must not be concurrently shared this
way. A real HTTP regression demonstrates that the old worker changes the
caller's server graph. A short initial stress did not reproduce the exact
historical SIGSEGV; that distinction remains part of the qualification.

Each existing HTTP worker now constructs and releases its own local MCPort
server and handlers. The scoped registry retains only explicitly allocated raw
bytes under a lock. Descriptors, completion state and bounded method diagnostics
are copied into the requesting thread's own strings and JSON nodes. No traced
server, session, closure, JSON graph or mutable sequence crosses that boundary.
Expiration frees the registry bytes and retains a final local snapshot for the
owning caller. Initialization is published before its response; first valid
completion still wins, coding receipts remain durable, and expired tokens
cannot complete a replacement session. The same scoped catalogs and access
policies remain in force. There is no extra server thread, agent, provider,
dependency or permission change. Malformed JSON reaches MCPort's structured
parse-error response instead of escaping the diagnostic parser as HTTP 500.

The separate repeated coding failure `Outgoing JSON must be UTF-8` came from a
persisted ticket whose agent-note preview began inside a multibyte character.
Byte slices could split characters in message tails, review feedback, rule and
spec summaries, and activity labels. These boundaries now preserve complete
UTF-8 characters within their byte budgets. For existing malformed historical
text, prompt bindings explicitly display invalid bytes as `\xNN`, with a notice;
valid text is unchanged. Original artifacts and their Git history are retained.
This is a prompt projection, not a rewrite of tickets, specifications or logs.

Qualification includes all offline tests; ACP lifecycle fixtures under ARC and
ORC; real scoped HTTP initialization, malformed input, isolated role catalogs,
concurrent completions, registry churn, explicit collection, expiration and
unchanged caller-owned graphs under ARC and ORC; and a read-only valid-prompt
proof using the exact retained malformed ticket. `make integration-test-mcp`
selects the finite HTTP suites without any AI provider calls. The pre-existing
HTTP fixture now supplies its required nonempty summary, verifies rejection of
an empty one, and shuts down and joins its owned server.

Production recovery stays with the existing Guildhall owner and campaign
coordinator. Preserve the exited container/crash, native attempts, ticket and
review/merge evidence. Publish the qualified package for normal target-only
adoption; do not replay old human operations, recreate the planning graph,
