# v20: ACP agent execution

Replace Scriptorium's backend-specific harnesses with one threaded ACP v1
runtime using ACPort. Support Codex and Claude through the official ACP
adapters and Grok through its native ACP stdio interface. Preserve Git state,
worktree isolation, the shared manager/coder slot pool, sequential review and
merge gates, and the requirement to call the scoped `submit_pr` MCP tool.

## Behavior and compatibility

Named `acpAgents` profiles define executable, argument array and environment
overrides. Roles select `acpAgent`; models, effort and deadlines remain
role-specific. Translate `codex`, `claude-code` and `grok-build` harness values
without changing files on reads. Explicit ACP settings take precedence. Retire
typoi and Hermes runners; arbitrary ACP agents can use custom profiles.

Prefer advertised ACP configuration options. Set the model before effort,
refresh dependent options, and reject unsupported explicit values. Preserve
configured model identifiers; omitted models use the agent default.

Deliver callback data through owned channels to Scriptorium's runner thread.
Stream structured transcripts to disk; stderr is diagnostic only. ACPort owns
transport and process cleanup. Scriptorium owns access policy, watchdogs,
continuations and ticket outcomes. Normal ACP completion alone cannot enqueue
work for review.

Reuse sessions only for the same conversation, role, assignment, directory and
access policy. Keep a coding assignment's MCP endpoint alive across turns.
Persist identity without credentials or scoped MCP URLs. Restore advertised
sessions after restart; otherwise record a fresh recovery conversation using
current repository and ticket context. A restored session must receive a new
MCP endpoint. Persist submission receipts before replying to `submit_pr`.

Read-only requests must use an enforceable restricted agent mode and reject
mutating or ambiguous permissions. Preserve operation-specific write guards.
Cancel cooperatively, allow five seconds, then use ACPort's bounded close.
Heartbeat rendering and diagnostic chatter are not agent progress.

## Validation and delivery

Mocked runners and protocol fixtures belong in unit tests. Real integrations
must use actual components and fail on missing prerequisites. Named Make
targets select suites without environment-based skipping. Run each suite once
per validation stage and rerun only for failures or relevant changes.

Validate streaming, model/effort selection, permissions, MCP completion,
multiple turns, restart, cancellation/reuse, concurrent isolation and shutdown.
Each supported backend must complete a small real spec-to-merge workflow.
Keep the development branch unreleased until these gates pass.

When dogfooding, have the architect reconcile existing spec sections rather
than append this checklist. Follow `docs/plan_prompting.md` and
`docs/version-runbook.md`; use an isolated clone whose default branch is the
v20 branch and disable remote synchronization.

## Validation record (2026-11-12)

- Reproduced the original v19 source check and unit suite with its locked
  dependencies. Baseline failures came from global dependency drift and Nix
  library paths; isolated setup now verifies the actual package commits.
- Offline unit coverage: 48 test files, including correctly reclassified
  mocked orchestrator/review workflows. Reran failing files after fixes.
- ACP lifecycle: 15 protocol-peer unit cases pass under ARC and ORC, including
  callback ownership, final event draining, native reuse, replay isolation,
  settings, permissions, symlink paths, typed RPC/transport errors, bounded
  retry/cancellation, and completed-session retirement.
- All 15 general integration files pass with real Git, HTTP, MCP, live intent
  classification, live review, daemon submission, and clean shutdown.
- Each of Codex, Claude, and Grok passes five live ACP cases: streaming/settings,
  native turns and restore, read-only enforcement, real writes plus scoped MCP
  rebinding, cancellation/reuse, and two concurrent isolated conversations.
  (Streaming/settings/native turns/restore share one case.)
- Each backend completes the Project Euler spec-to-merge workflow with real
  Architect, Manager, Coding, Review, MCP completion, quality gates and daemon
  shutdown. No mocked agents or skipped prerequisites are used.
- Fixed issues exposed by these runs: lost final reply chunks, inactive HTTP
  shutdown, oversized HTTP worker pools, missing MCP submission summaries,
  implicit review approval, idle shutdown delays, recovery selecting ordinary
  work while the default branch was unhealthy, and output budget replenishment
  when completed-ticket counters were cleaned up.

Chat routing is covered by offline Discord/Mattermost tests; no messages were
sent to external chat services. The existing audit CLI/automatic trigger remains
disabled pending its separate stabilization. The audit execution path uses ACP.

The isolated dogfood clone used `acport-integration` as its default branch and
`remoteSync.enabled: false`. The real Codex Architect reconciled the existing
spec in place and committed only `spec.md` (`2c087b4`). Its result is retained
locally on `scriptorium/acport-plan` for review. The spec covers the ACP runtime,
profiles, access, session recovery, MCP state, resource accounting, and existing
Git orchestration behavior; it does not append a release checklist or create
work tickets.

The Nix shell packages the same checksum-pinned upstream Nim 2.2.14 compiler
used on the host/Docker. `nix develop` successfully compiled Scriptorium and
ran its version command. The old nixpkgs compiler patches did not apply to the
new compiler, so the shell uses the upstream binary with Nix ELF relocation
instead of carrying compiler source patches.

Docker builds and runs the development image with all pinned tools present.
Compose configuration validates without a `.env` file; Mattermost is an optional
`chat` profile. Dependency/tool installation is cached separately from source
compilation. No images, tags, branches, or chat messages were published.

After these gates passed, the package, CLI and ACP client identity were advanced
to 20.0.0. The release remains local on `acport-integration` for review.

Final artifact smoke checks: the native binary and local Docker image
`scriptorium:20.0.0` both report 20.0.0. Inside the image, all three CLI versions
and both official adapter versions match the pins above. The final image was
built from `1c4f8d8`; only documentation changed afterward.
